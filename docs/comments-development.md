# 视频评论：研究与实现

来源：niudungh/bilibili-comment-skill，核对提交034978ae596ce8d28689149262e75a0acddfc36e。Python标准库CLI，主评论游标分页、置顶合并、楼中楼页码分页、JSONL扁平记录、断点续采。README/SKILL声明MIT，未附独立LICENSE；原样复用flatten.py并保留来源和许可说明，其余实现适配本项目。

研究发现：原CLI的max是主评论上限，楼中楼仍可能很大；页末才保存游标，JSONL与状态不原子；完成后的since不会重新扫描；固定按20条判断楼中楼末页可能受服务端页尺寸影响。本入口不照搬这些完整性假设。

设计决策：command-led采集与reading-led评论检查。P1评论文本；P2作者、时间、点赞、回复结构；P3采集范围/完整性与来源；Action采集、筛选、导出。数据来自真实API，不显示虚构情绪分析。移动端[链接+参数][状态][筛选][评论线程]，宽屏[采集与资料库 | 筛选+线程阅读]；极宽屏正文控制行宽，旁侧提供采集范围。沿用现有绿色操作色、纸面正文、Lucide图标、6px控件与细线；评论缩进连接父子关系为唯一签名。无装饰卡片。重点风险：楼中楼长文本/长作者名溢出；控制区堆叠阻塞移动端采集。验收五尺寸、键盘、错误/空状态、采集进度、楼中楼、筛选及导出。

工程：固定B站API地址、不跟随携带Cookie的重定向；使用显式保存的B站凭据，任务临时Cookie加密并在结束后清除。单工作线程、至少1秒请求间隔、有限指数退避。独立comments任务/评论记录，成功或失败保留真实快照，重试复用持久状态。单次主评论/总评论双上限；热门/最新是平台采集顺序，页面点赞/时间排序只作用于已采集数据。

仅在用户点击“分析筛选后的评论”时向所选LLM发送匹配的评论正文，不改变视频专家解读的输入。评论以React纯文本显示，不渲染用户HTML；详情导出JSON/JSONL/Markdown，隐藏原始用户ID/IP位置/性别等非必要字段。评论来源、采集时间、平台声明数量和范围状态分开显示，不把数量接近当完整证明。

## 接口与使用

- POST /api/comment-jobs：url、credential_id或临时cookie、order（hot/latest）、max_top（1..1000）、max_total（1..5000）、include_replies；总上限不能小于主上限。返回任务id与快照result_id。
- GET /api/comments：只返回快照摘要，详情GET /api/comments/{id}按需加载。
- GET /api/comments/{id}/export?format=json|jsonl|md：独立下载。
- 复用 /api/jobs、失败重试、排队取消和服务重启恢复。失败重试沿用同一快照/命名空间；新采集创建新快照，不冒充增量同步。只采主评论或达到上限明确显示部分范围。

页面新增“视频评论”导航；文字稿标题旁也有入口，会预填当前视频。当前视频没采集记录时显示空状态，避免错配其他视频。主评论按线程分页（20条/页），楼中楼按根评论展开；搜索匹配内容/作者，UP主过滤保留相关父线程作上下文，排序作用于已采集主评论，不改变远端采集顺序。

## 评论模型分析设计（本轮）

reading-led观点报告，继续使用design-visual-frontend。P1观点与结论；P2论证/例子/分歧；P3精确筛选范围与原评论；Action设置最小/最大字数、选择模型、生成及核对。移动端[字数/搜索][模型与条数][总览/逐条][报告/原评论]；宽屏[采集/资料库 | 筛选/模型/报告/原评论]，宽侧栏维持采集范围职责。保留绿色控件与正文排版，编号引用是连接分析与原评论的签名。不加入装饰性情绪分数。

字数按去除空白后的Unicode码点数，标点与表情保留；上下限闭区间。关键词、仅UP主评论和字数共同筛选每条评论，父线程未匹配时仅在阅读中保留作上下文，不送入模型。分析固定提交时筛选范围/评论快照/模型，轮询和后续采集变化不会改变该任务输入。输出总览+逐条观点、结论/表达结果、理由、具体举例与原话依据；没有例子不编造。分片结构校验、全部编号覆盖、原话必须匹配本人原评论；汇总引用只能使用已解析编号，保留全部逐条结果与历史/导出。非法引用/缺失结果至多修复一次，检查点供失败重试复用。超量要求调整筛选，不暗中抽样或截断。


### 模型分析接口与工程约定

- POST `/api/comment-analyses`：comments_id、provider_id、min_chars（默认20）、max_chars（可空，不限）、query、up_only；返回独立任务id。采集期间不可提交；无匹配或超过单次500条/10万字符/单条12000字符时明确拒绝，页面显示原因。
- GET `/api/comment-analyses`：结果摘要；GET `/api/comment-analyses/{id}`：完整报告；GET `/api/comment-analyses/{id}/export?format=md|json`：报告下载。失败沿用已有任务重试接口，原始评论与模型配置冻结。
- 新增 `comment_analysis.py` 作为独立评论引擎，复用已有供应商协议；评论结构化纠错保留上一份输出，定位到具体来源编号与字段。每批最多6条评论；每条最多4个观点，每观点最多8条论据/4个例子。不同评论同主题归组时保留各自结论和引用，不强制填满结构。
- 原评论以C编号送模型，昵称、平台用户标识、Cookie不送入模型；未通过字数/搜索筛选的父评论只在网页列表作上下文，不作为模型材料。缺失父语境显式提示。
- 原话引用必须是对应评论的连续文字，汇总举例只能引用已核对的例子编号；校验保证编号/原话存在，不保证模型语义判断正确，不构成事实核实。
- 原话弹窗、逐条分页、无观点条目开关、历史报告选择和独立MD/JSON下载共用稳定报告契约；原视频的财经/程序员专家配置、历史报告和文章入口保持兼容。
